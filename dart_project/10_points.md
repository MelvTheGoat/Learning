1. **Format Detection & Data Extraction (Part A):** The `normalizeSuccess` function handles the two divergent provider formats (OpenAI vs. Internal) using structural detection rather than relying on a provider type parameter. It explicitly checks for the existence of the `choices` key (indicating OpenAI format) versus the `output` key (indicating Internal format). If a payload matches neither (or contains malformed data, like the string `"unknown"` for token counts), it fails loudly by throwing a `FormatException` rather than silently coercing bad data or guessing the format.

2. **Error Handling & Security Constraints (Part A):** The `normalizeFailure` function implements a strict error taxonomy, checking payload error codes (like `content_filtered`) before HTTP status codes, as providers often multiplex distinct errors over generic 400-level statuses. Crucially, to prevent credential leakage (a specific trap in the `provider_content_filter.json` fixture, which contains a bearer token), the normalizer uses *only* hardcoded, static strings for error messages. It never copies arbitrary string data from the upstream payload into the canonical response.

3. **Strict Fallback Gating (Part A):** The `decideFallback` logic acts as a defense-in-depth gatekeeper. Fallback is permitted if and only if three conditions are met: a distinct fallback provider is configured, fallback hasn't been attempted yet, and the error code is explicitly eligible (`timeout` or `providerUnavailable`). We explicitly reject fallback for quota-related errors like `rateLimited`, as failing over would simply burn the fallback budget without resolving the underlying quota exhaustion.

4. **Math Constraints & Edge Cases (Part A/B):** The `cosineSimilarity` implementation explicitly validates against edge cases: throwing exceptions for empty vectors, dimension mismatches (refusing to silently pad shorter vectors), and zero-norm vectors to prevent division-by-zero errors. 8. **Resilience & Failure Policies (Part D):** To maintain stability under load, the design implements two key policies: Tenant Quotas and a Fallback Budget. High-traffic tenants are capped at a soft limit of 50% of available concurrency to prevent monopolization. Crucially, fallback traffic is capped at 20% of total volume. Without this cap, a total primary outage would instantly route 100% of traffic to the fallback provider, likely triggering a cascading failure that brings down both systems.

If the AI tool wastes engineer time with inaccurate reviews, the hidden cost of human review time (e.g., $1/min at a 40% false positive rate equals ~$48K/mo at scale) will dwarf the $13.5K inference savings. Therefore, the pilot cannot just measure speed; it must establish baseline metrics for user experience (UX) and post-merge defect escape rates to prove true ROI.
